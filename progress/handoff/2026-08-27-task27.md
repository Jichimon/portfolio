## The four slices

Verify current file counts before slicing (`S-03`: no directory under `site/**` holds 7+ files, except a package root) — this packet's counts are a snapshot from 2026-08-27 and may be stale.

**Slice 1 — the extractor as its own module.** `extractBoard` moves out of `local-preview.mjs` into `docs/design/canvas/extract-board.mjs`, with `node:test` tests, and `local-preview.mjs` imports it. While there: the `BOARDS` array in `local-preview.mjs` is a hardcoded 15-entry roster duplicating what `canvas.json` already declares — read it from there instead (`P-13`).

**Slice 2 — the route↔artboard mapping.** Each artboard in `canvas.json` declares `route`, `viewport`, `theme`. The mapping itself is a decision (declared, not derived); what's checked is a property: every live route has a mapped artboard, or a declared exemption with a reason. Known exemptions: the four `pass 0` history artboards (`DirectionB/C/CDark`, `MobileSeam`), and `Components.dc.html` (a sheet, not a page). Extend `verify.mjs` and its test.

**Slice 3 — the diff itself.** New directory `site/tests/fidelity/` (check the current file count in `site/tests/e2e/` first — it was at 6 in this session, and `S-03` caps at 7 including any new file). A `fidelity` project in `site/playwright.config.ts`. For each component present on both sides: computed color, typography, spacing, and box geometry (width, height, gaps), compared with a tolerance — **never text equality**, since artboards carry mockup content by design. The compared property set and tolerance live in `guards.config.json` with a stated reason, not as literals in the spec.

**Slice 4 — the gate step, the prod skip, and the red battery.** A `design fidelity` gate step, separate from `e2e smoke` (different browser-engine scope: fidelity runs chromium only). The prod leg's module reads its base URL from an environment variable; unset, it reports `skipped — no deployed build exists yet (TASK 32)`, never `PASS`. Red battery, all four proven, not just seen once: (1) change a token value → fails; (2) remove a component's border → fails; (3) delete a mapped artboard → fails, does not silently skip; (4) no env var set → `SKIPPED` with a named reason, never `PASS`.

## The three real defects this mechanism has to catch — proof it's built right, not just built

The last two page-implementation items (`TASK 24`, `TASK 26`) each closed noting that automated checks were green while design defects shipped, found only by looking. Concretely:
- A page inset applied twice (component rendered a `<section>` inside the page's own) — this is **geometry** (box height/padding), caught by slice 3's box comparison.
- A missing border on a component — this is **computed style**, caught directly.
- An `HTTP 404` string duplicating the status line in the numeral's display slot — this is **structure**, caught by slice 2/3's per-component comparison, not by any pixel mechanism.

If the finished mechanism, run against the working tree as it stands today, does *not* flag anything (these three are already fixed), that's expected — the value is in the red battery reproducing each failure mode deliberately, not in re-finding fixed bugs.
