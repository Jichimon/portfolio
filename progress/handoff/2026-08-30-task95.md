## The goal, in one sentence

Make a `DIRECT_WRAPPERS` candidate (`env`, `timeout`, `sudo`, …) get recursed back through `commandContexts` instead of pushed as a raw, terminal `argv` array — so a `FLAG_WRAPPERS`/`EVAL_WRAPPERS` command reached *through* one of them is unwrapped the same way it would be at the top level.

## The extract — read this, not the sources first

**The defect, verified this session** (`node -e` against the real functions, `scripts/guards/lib/path-boundary.mjs` and `scripts/guards/lib/git-write.mjs`):

```text
{"allowed":true,"findings":[]}  <-  env sh -c "cat private/glossary.md"      (H-04)
{"allowed":true,"findings":[]}  <-  env eval "cat private/glossary.md"      (H-04)
{"allowed":true,"findings":[]}  <-  env sh -c "git commit -m x"             (H-01, via checkGitWrite)
```

Contrast, already caught (proves the gap is specifically about a wrapper reached *through* `DIRECT_WRAPPERS`, not a general `DIRECT_WRAPPERS` failure):

```text
{"allowed":false,"findings":[...]}  <-  env timeout 5 git commit -m x
```

**The cause**, `scripts/guards/lib/shell.mjs` (`commandContexts`, currently around line 322-329):

```js
if (DIRECT_WRAPPERS.has(head)) {
  for (let i = 1; i < argv.length; i++) {
    found.push({ argv: argv.slice(i), raw: seg, via: [...via, head], env: [] });
  }
}
```

This offers every argv **suffix** as its own terminal candidate — it never calls `commandContexts` again on that suffix. That is why `env timeout 5 git commit -m x` works: one of the offered suffixes (`['git','commit','-m','x']`) is itself a bare `git ...` argv the boundary checkers match directly. It is also why `env sh -c "cat private/glossary.md"` does **not** work: the offered suffix `['sh','-c','cat private/glossary.md']` is a raw argv nobody re-examines for being *itself* a `FLAG_WRAPPERS` invocation — `sh -c` needs the recursive unwrapping `commandContexts` already does at the top level (see the `FLAG_WRAPPERS` block a few lines above, and the `EVAL_WRAPPERS` block a few lines below, both of which call `commandContexts` again on the string they extract).

## The traps

- **The obvious fix — recurse on every offered suffix — will re-find the SAME suffix-as-plain-command case `DIRECT_WRAPPERS` already handles, just through recursion instead of a raw push.** Confirm the fix does not turn `env timeout 5 git push` into duplicate/triplicate findings for the same underlying command; the existing test `commandContexts: env/timeout/sudo-style wrappers offer every suffix as a candidate` (in `scripts/guards/lib/shell.test.mjs`) must keep passing unmodified.
- **Chained `DIRECT_WRAPPERS` (`env timeout 5 git push`) already works by brute force** — do not let a recursive rewrite accidentally rely on `env`/`timeout` being in `DIRECT_WRAPPERS` themselves for this to keep working; `commandContexts` recursing on `env`'s own suffix `['timeout', '5', 'git', 'push']` should re-enter the very same `DIRECT_WRAPPERS` branch naturally, one level deeper. Trace the recursion by hand before trusting it.
- **`depth` still has to increment on every recursive call**, exactly like the `FLAG_WRAPPERS` and `EVAL_WRAPPERS` recursions two blocks above and below — `TASK 93`'s own audit found a missing-depth-increment class of bug is easy to miss and easy to test directly (see `commandContexts: eval increments the nesting depth counter like every other wrapper` in the same test file for the pattern to copy).
- **This session's own two fixes (`TASK 92`, `TASK 93`) were each wrong on the first attempt, caught by a scoped `adversarial-auditor` pass run before closing.** Both fixes had passed their own tests and a full gate run before the audit found the gap. Run the same audit discipline here — `P-14`/`T-04`: proven in red, not just observed passing a happy path — before declaring this one done. `.claude/agents/adversarial-auditor.md`'s own instruction is to run "always on a guard or a boundary," and this is exactly that shape.
- **Verify against real bash, not just the guard's own logic**, the same way this session did for `TASK 92`/`93` (`bash -c '...'`, GNU bash is available via the Bash tool on this machine, Git Bash). A claim like "this recursion now unwraps `env sh -c "..."`" is worth confirming against what bash itself actually does with that exact string, not just what the guard function returns.
