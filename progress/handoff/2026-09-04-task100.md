Install one of the two bootstraps on one of the author's other projects and drive a single real work item there end to end, producing a scorecard from that run.


## The traps

- **The gate is red at `design canvas`, and it was red before any of this.** `TASK 119`. Do not spend a session diagnosing it as something the export broke; the canvas sources are unmodified against `HEAD`. And do not let a red headline train you to skim the summary — that is how it went untracked for at least one work item.
- **Do not run the gate through a pipe.** `node scripts/gate.mjs --profile full 2>&1 | tail -80` reports `tail`'s exit code, not the gate's, and discards every per-step line including the mutation score. This session did exactly that and had to re-measure. Redirect to a file and read the file.
- **Every living markdown file in this repository is CRLF.** A scripted edit matching `\n` finds no anchor and reports success having changed nothing.
- **`docs/**` is link-checked.** Any backticked token with a directory separator and a known extension must resolve. The export documents keep every target-project path inside a fenced block or behind a placeholder for exactly this reason — if you add prose to them, keep that discipline or `check-docs` fails.
- **Four things about the OpenCode environment are unsettled and are meant to be settled by this item**, not guessed: whether the plugin's before-execute hook runs before or after the permission map; whether anything fires when the rule files enter context; which delegated-run boundaries the plugin API actually emits; and whether throwing is genuinely what blocks. The bootstrap's smoke test has a line for each. **Write the answers into that project's architecture document as observed facts with the date** — that is the measurement `TASK 9` is waiting on, and it is worth more than a clean install.
