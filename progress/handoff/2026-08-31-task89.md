## The traps

- **`T-06` forbids the obvious fix, and the entry says so twice.** A retry is out. Clearing the cache as a build step is out — it hides the ordering bug rather than fixing it. If the session finds itself proposing either, it has stopped working the item.
- **The reproducing test is the hard part, and it may not be constructible.** A `bugfix` needs a test that fails before the fix (`T-01`), but this is a cache-state race in a third-party runner, not a pure function. If no repro can be forced, **that is a legitimate outcome to report** — `blocked` or `partial` with what was tried, per `wrap-up` §2 — and it is worth far more than a green claim resting on runs that happened not to fail. `TASK 85` is the sibling item that stayed open for exactly this reason.
- **Three clean runs is not a close.** `TASK 85`'s entry already records that standard being set and refused: three consecutive clean `gate.mjs` runs is *insufficient* to close a flake without a repro. Point 3 above is a data point, not a resolution.
- **Do not merge this with `TASK 69` or `TASK 85`.** Same class, different tier and different runner (Playwright, not Vitest), and `TASK 85` has no captured repro at all. If a shared root cause emerges, that is a finding for whichever runs second — recorded, not folded.
- **`P-19` still applies.** If working this opens three more items in the Vitest/Vite configuration surface, that is the `INC-17` shape recurring one tier over. Ask which goal each serves before opening it.
