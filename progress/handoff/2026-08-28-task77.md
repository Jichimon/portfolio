## The traps — each of these has already cost something here

- **`0` is not an absence.** A transcript that cannot be read must record that fact, never a zero. `TASK 70` shipped with `researcher` reading 0.00 MB across 158 turns because `WebFetch` records ~78 bytes per result, and that report now has to partition on a fix date forever. Do not create the second instance.
- **Integers only, and this is the confidentiality boundary, not a style rule.** The transcript holds everything that was said, including anything read near `private/`. `docs/harness/evidence.md` states the trace records *what was attempted, decided and happened* — never *what was said*. The extractor pulls named numeric fields and nothing else: no message id, no error text, no `model` string it did not itself derive from a known set. **The red battery plants a `private/`-shaped string in a synthetic transcript and asserts it cannot appear in any written event.**
- **`H-03` — you may not write to `evidence/` by any vector.** The hook writes; you write the hook. Testing means calling `eventsFor` with a synthetic input, never touching a real trace file.
- **One write path only.** `eventsFor` in `scripts/guards/lib/evidence.mjs` builds every event. Do not add a second, and **do not register another hook** — nine are registered already, each costs a process spawn per tool call, and that latency is measured (~200 ms per process, ~145 ms of it bare Node boot).
- **A new event needs a `SCHEMA` row.** `scripts/guards/lib/evidence.mjs` carries a `SCHEMA` table keyed by `ev`; `check-trace` reads it. An event with no row is an event nothing validates.
- **`TASKS.md` is CRLF.** A `\n` literal will not match it, and a JS `.` does not match `\r`. This has caused two silent no-ops in the last two sessions.
- **`sed -i` and `perl -pi` silently no-op on this machine.** Long heredocs truncate. Use the file tools, or Python with `newline=''`.
