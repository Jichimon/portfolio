**Inside the gate 0 of 2. Alone 2 of 2.** The full dataset and the reasoning live in `TASKS.md` § `TASK 69`, which this session rewrote around it.

**Three hypotheses already killed, so nobody spends a run re-killing them:**

- **Not the content.** Run 3 failed `GET /` and `GET /es/`, and several tests timed out at `browserContext.newPage`, before any navigation. Markdown cannot do that, and the suite passed twice on the same files.
- **Not gate-internal parallelism.** `scripts/gate.mjs` drives every step through `spawnSync`, sequentially. Verified by reading the runner, not assumed.
- **Not a timeout five seconds too short.** 2.5 min against 49.3 is a 20x swing. `TASK 57` already established that raising the budget closes the symptom and nothing else, and `TASK 69`'s `Done` forbids that fix explicitly.

**The one positive signal:** run 1's error was `NS_ERROR_CONNECTION_REFUSED` and the line directly above it in the gate output was `Stopped preview server (pid 262964)`. Refused is not slow, it is absent. At least that instance is a teardown racing a worker that still had a test in flight.

**Where to look:** what the preceding gate steps leave the machine in when `e2e smoke` starts. The step before it is `type check`; two steps before is `component tests`. The suite manages its own preview server in `globalSetup`.

## The traps

- **`H-02` is rung 1.** No agent writes `resources/**`, by a `deny` rule and by the `resources-readonly` guard. If a fix seems to need a content edit, it is the wrong fix.
- **There is no such thing as a skeleton `done` block.** `check-procedures` rejects an empty one, a missing one, and one without `iterations`. `progress/README.md` now documents this. Write a complete block the moment you open the log, with `iterations` reading the count to date.
- **Green guard tests do not imply a green `procedures` step.** This session saw `guard tests 1050/1050` while `check-procedures` was red. Different assertions.
- **A human refusal leaves no trace event** (`TASK 105`). A refused call reads as `policy.decision: allow` plus no result, identical to a call still in flight. Do not read an orphaned request as delivery loss without checking whether someone said no.
- **`component tests` flakes about one run in seven** (`TASK 89`). A different tier from `TASK 69` and a different failure. Re-run the step alone before believing it.
