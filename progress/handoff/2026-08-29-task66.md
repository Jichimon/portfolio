## The trap this hands you

**`TASKS.md`'s own status field has no history today — only current state.** A line reading
`· \`DONE\`` does not say *when* it became `DONE`, and a reopen (`DONE` → anything else) leaves no
trace unless something records the transition at the moment it happens. Do not solve this by
parsing git history or diffing the file over time — `H-01` means agents cannot commit, so git log
timestamps reflect *the human's* commit cadence, not the moment the status changed in-session, and
`check-procedures` already reads the working tree, not git. The dated, greppable line has to be
written into `TASKS.md` (or a sibling artifact it derives from) by whatever process changes the
status, the same session that changes it — most likely the `work-item` procedure's own step 6
(Reconcile) or `wrap-up`'s step 1, both of which already touch `TASKS.md`'s status line as a
matter of course.
