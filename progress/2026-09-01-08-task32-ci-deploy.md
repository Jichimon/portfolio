## Three decisions taken with the author before the spec

Recorded here as well as in the register, because a decision that lives only in a conversation is one the next session re-litigates (`P-10`).

**1 · One workflow file; the deploy is a `job`, not a `.yml`.** `check-docs` validates the CI workflow by name, so a second file lands with no path-filter check, no gate-parity check and no Node floor — `INC-08`'s shape arriving through a filename. A `deploy` job with `needs: gate` carries no guard gap and runs the gate **once** per push. The two-file shape could not manage that while also honouring the item's own *"the workflow runs `npm test` before deploying"* constraint: `deploy.yml` would have re-run the whole gate after `harness.yml` had already run it.

**2 · `harness.yml` → `ci.yml`.** The author asked for the rename; the name was chosen after the trade-off was stated. After this item the file gates on **every** trigger and deploys on **one** — a PR run, a nightly `full` run and a push to any other branch all verify and ship nothing. `deploy` would misdescribe the majority of its runs. Two costs, stated up front rather than discovered: GitHub opens a **new** entry in the Actions tab, so runs `33570798170` and `33571567866` stay reachable only under the old name; and the README badge is dead until `ci.yml`'s first run.

**3 · `TASK 27`'s prod comparison goes back to `TASK 27`.** The item's third `Done` clause read *"`TASK 27`'s prod comparison is switched on and passing"*, and that was unreachable: `TASK 27` is `TODO` in full, `site/tests/e2e/` holds five smoke specs and no fidelity-diff suite, so there was no prod target to switch on and no work inside this item that creates one. One item's done cannot be another item's deliverable (`P-01`). Replaced by a clause this item can meet and mechanize: **every route the collection derives returns 200 at the deployed URL.** What this item owes `TASK 27` is exactly what that leg was waiting on — a published base URL, named `PROD_BASE_URL`.

## What the mutation read found, and why it was worth reading rather than trusting the aggregate

**The gate passed at 79.54 against a floor of 77.0 with `deploy-verify.mjs` sitting at 77.92 — 15 survivors and 2 mutants with no coverage at all.** The aggregate went UP because two well-tested modules entered the denominator, and that is exactly how a weak battery hides inside a healthy number. `T-03` says a surviving mutant is a finding, not a statistic, and this is the case it was written for: the module in question is the one deciding whether a deploy landed.

**Three of the survivors were vacuous assertions in tests written this session**, which is the more useful half of the finding:

| Survivor | What it proved |
|---|---|
| `baseUrl.trim()` removed — survived | The unset-URL test matched `/base URL/i`, and **both** the unset branch and the not-a-URL branch say "base URL". Whitespace fell through to the second branch and the assertion could not tell. Now asserted on `/unset or empty/` |
| `typeof baseUrl !== 'string'` — survived | Same defect, same test, other operand |
| `!Array.isArray(routes)` — survived | Only the empty-array half was ever exercised; a derivation returning `undefined` is the likelier real failure and nothing tested it |

The rest were genuine gaps: the readiness loop's `<=` bound (a one-attempt difference no inequality assertion can see), the `if (attempt < attempts)` guard that stops it sleeping after the last try, the **default `sleep` parameter which had no coverage at all** because every test injected one, and three regex anchors — unanchored, `about.en.md.bak` becomes a route the site does not serve and a stray `---` in prose parses as frontmatter.

**Eight tests added, no threshold moved, and the result re-measured cold rather than inferred:**

| module | before | after |
|---|---|---|
| `deploy-verify.mjs` | 77.92, **15 survivors, 2 with no coverage** | **96.10**, 3 survivors, **0 uncovered** |
| `route-source.mjs` | 90.32, 3 survivors | **96.77**, 1 survivor |

**Four survivors remain and three are suppressed at the mutant with a written reason** (`T-03`), never by lowering a number. `urlFor(baseUrl, '')` and `urlFor(baseUrl, '/')` resolve identically through `new URL(path, base)`, so that mutant is equivalent. Dropping the leading `^` from the filename matcher is equivalent too — `.+` absorbs any prefix, so anchored and unanchored accept the same set; the **trailing** `$` is not equivalent and the `.md.bak` test kills it. The default `sleep` is now covered but its *duration* is unobservable without asserting elapsed wall time, which would be a flake, and `T-06` says a flake is a finding — killed for coverage, suppressed for behaviour.

**The fourth was killed rather than suppressed**, and it was the one worth arguing about: the `(none)` fallback in the content-type message. A missing header and a wrong header are different deploys gone wrong, and a reader of a failed CI log should not have to guess which — so the test now asserts the message says so.

**The edit carried a defect independent of the Workers-versus-Pages question, and it is the more useful finding.** `pages deploy site` uploads the `site/` **directory**, not the build:

| path | files |
|---|---|
| `site/` | **21,568** — over Wrangler's 20,000-file Pages limit, so the deploy fails outright |
| `site/` minus `node_modules` | 350 |
| `site/dist` | 134 — what actually gets published |

Had the limit not caught it, the deploy would have published `src/`, `tests/` and both lockfiles to the open internet. **The Workers form takes no directory argument at all** — `wrangler.jsonc` names `./dist` relative to itself — so the class of mistake is unavailable there, which is a property worth noticing rather than a coincidence.

**Two things would also have had to happen outside the repository**, and neither was obvious from the diff: a Pages project must exist *before* the first deploy, because CI cannot answer the interactive prompt that would otherwise create it; and the API token needs `Cloudflare Pages: Edit`, where the one already created is scoped `Edit Cloudflare Workers`. Both verified against Cloudflare's own docs rather than recalled.

**`ADR-004` is what caught this**, which is the ADR index doing exactly the job its own preamble claims: a decision reversed by editing one line of YAML, with no record, is the failure `P-07` and the level-2 table exist to prevent. The Pages path also has a documented one-way door — a Direct-Upload project cannot later switch to git integration — so the reversal would have been expensive and silent. Nothing about the ADR changes; it was consulted, it held, and that is recorded here rather than nowhere.
