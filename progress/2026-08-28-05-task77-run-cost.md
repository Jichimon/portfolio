## Decisions
- **The "since the previous such event" boundary excludes `observed` run.header events**, using only `startup`/`delegated` headers or a prior `run.cost` as the boundary — why: `posturePatch` injects an `observed` header mid-dispatch on a permission-mode change, which is not a resume boundary; treating it as one would silently truncate the token/wall-clock window. Verified live on a real resumed dispatch: `wall_ms` matched a hand-computed figure (from the real `delegated` header, not the later `observed` one) to within 7ms.
- **`message.model` is validated against `/^claude-[a-z0-9]+(-[a-z0-9.]+)*$/i` before use as an object key**, falling back to the sentinel `unknown-model` — why: it is transcript text, and copying it verbatim would be a second, unaudited path for arbitrary text to reach the trace. Rejected: relying on the redaction scanner alone, which would catch a literal banned term but not honor the brief's "not a model value it did not itself derive from a known set."
- **Deduplicate by `message.id`, keep the last snapshot per id, before summing** — why: found live, not designed in from the start (see Findings below). Rejected: keying off `stop_reason` to detect a message's final block, because it is inconsistently populated even on a real final `tool_use` block.
- **No `ADR-009` amendment.** Its §8 design was implementable as specified; what it left open (the boundary mechanism, the model-string trust) is ordinary implementation detail, not a contradiction.
- **`TASK 78` (cost per completed item) stays untouched**, including `check-cost.mjs`/`cost.mjs` — confirmed those modules silently ignore event types they don't recognize, so `run.cost` appearing in a real trace does not break today's report.

## Open questions
- `EC-005`'s notes are stale (see loose_ends above) — worth a re-score, not urgent.
- The transcript's async-write lag (documented by the runtime: "may not yet include the current turn's most recent messages when a hook fires") means a `run.cost` event can under-count the trailing message(s) of a dispatch whose SubagentStop fires while the transcript writer is still catching up. Observed directly: the first (buggy) run.cost read a partially-flushed transcript and its numbers didn't match either a naive or a deduped recount against the fully-flushed file afterward. Not fixable from inside a hook that must exit fast and never retry-loop; stated here so the next person who notices a `run.cost` slightly undercounting a fast-finishing dispatch doesn't treat it as a new bug.
