## What was done

`renderLedger`'s 27 surviving `CallExpression` mutants — every one deleting a push of a blank line or a prose sentence — were killed by asserting the artifact's **shape** rather than its sentences. New module `scripts/guards/lib/markdown-shape.mjs` checks that a generated Markdown document is well-formed: four rules over block structure, quoting no prose. The 16 survivors the register's entry never mentioned, outside `renderLedger`, were taken one at a time: 14 killed by named tests, 2 declared equivalent and suppressed at the mutant with the run that proves it. `status-history.mjs` now carries **zero survivors and zero uncovered**; the surface re-measured **77.58%** and the floor ratcheted 76.0 → 77.0.

## Decisions

- **The rendering half stays INSIDE the mutation-covered surface, and `D3` gains a distinction it did not have:** a render template's *sentences* are noise and stay suppressed at the mutant with a written reason; a render template's *shape* is structure and is asserted, never suppressed. Recorded as standing policy in `stryker.config.mjs` and `30-testing.md`, for every future `lib/` module that renders — which is what the entry's third constraint asked for.
- **The reframing the whole item turns on: a blank line in Markdown is not prose, it is syntax.** Drop the one between a paragraph and a table and the table stops rendering; drop the delimiter row and there is no table at all. The ledger's reader is `harness-evaluator`, which reads it *as a Markdown document*. So the 27 were never equivalent mutants — they were real defects that survived because every assertion on that artifact matched content with `[\s\S]*` and none asked whether the document was well-formed.
- **Rejected — a golden-file snapshot.** One `assert.equal` would kill all 42 and let the `StringLiteral` suppression be retired, but every prose edit then regenerates the fixture, and an artifact regenerated by reflex is a control that stops being read. That is the failure mode `mutation-suppressions.mjs`'s own header records this repository hitting three times.
- **Rejected — excluding render templates by a `*.render.mjs` naming convention.** It is a declared property rather than a roster, so it satisfies `P-13`, but it discards the 49 mutants `renderLedger` currently kills, including every section guard and every data row `TASK 66` measured as worth killing. Protection down, score up — and measurably so: it would have *raised* the aggregate to 76.69 by deleting the evidence rather than the defect.
- **Three redundant guards deleted from the new module rather than suppressed.** Its own mutation run reported them as unkillable, which is what a redundant guard looks like from the outside. Removing a guard because a mutant survived is the wrong move when the guard is load-bearing and the right one when it is not, and the difference was checked by running each mutant rather than by reading.

## Findings from validating against real state (P-04)

- **Three of the register entry's numbers were estimates and are wrong.** Measured from `reports/mutation/mutation.json` (the run that closed `TASK 67`): the entry says "~40 surviving `CallExpression`" in `renderLedger`; the real figure is **27**, plus one `ArrayDeclaration` on `const L = []` — 28. The entry says 35 `StringLiteral` suppressed; the file reports **49 `Ignored`** in that function, because the block directive is wider than the lines one mutator covers. Corrected in `TASKS.md` rather than left standing.
- **The entry does not mention that the file has survivors outside `renderLedger` at all** — there are **14 more, plus 2 `NoCoverage`**, for 42 in the file. Its `Done` says "no surviving mutant that a reader would have to re-triage", which covers them, so they were done too.
- **The entry's central claim held up.** All 28 in `renderLedger` are `L.push('')` or `L.push('<prose>')`; not one is a data row or a section guard, and the 23 `CallExpression` mutants on data rows and section headings are already killed. A function-wide `Stryker disable CallExpression` really would have given up 23 real kills to silence 27.
- **One test looked like it covered two defenses and covered neither.** `readRevisions` splits git's output behind both `.trim()` and `.filter(Boolean)`. A single test with leading and trailing padding killed **neither** mutant, because each defense fully compensates for the other's absence on that input. Found by neutering, not by reading; split into two tests, each carrying the input that isolates one defense — whitespace-only padding, which `filter(Boolean)` keeps because it is truthy, and an empty line in the middle, which `.trim()` cannot reach.
- **The new module entered the mutation-covered surface with 41 survivors of its own** — a checker built to find untested code, itself untested, which is the item's own defect one level up. Reading them rather than suppressing them found: a `kind` field on every block that was written and never read (so every one of its mutants was equivalent *by construction* — dead data reporting as untested code); an `isHeading` classifier that was not load-bearing, since a heading block and a paragraph block are both one line and the only rule that cares re-tests the line itself; and three redundant conditions whose mutants were unkillable because the guard beside them already decided the same thing. After removing all of it: **100.00%, 141 killed, 8 timed out, zero survivors, zero uncovered, and no suppression at all.**
- **Two mutants in `status-history.mjs` are genuinely equivalent, and that was proven rather than assumed.** `if (n > 0)` in `validateReopenDeclarations` — the reader takes `declared.get(id) ?? 0`, so a stored zero and an absent key are the same value; and `c < d`, where the line above already `continue`d on `c === d`, making the only separating input unreachable. Both were run against the battery and both survived, which is what the suppression comments cite.
- **`30-testing.md`'s stack-dependent row still read `break: 75.5`** — two ratchets behind, stale since `TASK 66` raised it to 76.0 on 2026-08-29, and found only because this item came to turn it again. `P-07`'s characteristic failure, in the document that defines the rung. Reconciled in the same pass, with the staleness recorded in the row rather than quietly fixed.
